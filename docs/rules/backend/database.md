# Database: Prisma + PostgreSQL

Local development uses PostgreSQL installed on the machine (`localhost:5432`), database `saas_kit`, role `postgres`. Prisma ORM **7** (GA) — not Prisma 8 RC.

## Directory Structure

```text
prisma.config.ts                  # ONLY Prisma file outside shared/prisma — CLI config at app root
src/
└── shared/
    └── prisma/
        ├── schema.prisma         # Data model — single source of truth
        ├── migrations/           # Generated by prisma migrate — none until the first model
        ├── generated/            # Prisma Client output — gitignored, never hand-edited
        ├── seed.ts               # Idempotent seed script
        ├── prisma.module.ts      # Global Prisma module
        └── prisma.service.ts     # Extends PrismaClient (driver adapter), handles lifecycle
```

## Prisma Service

- Create a single `PrismaService` extending `PrismaClient` with `OnModuleInit` / `OnModuleDestroy`.
- Pass `@prisma/adapter-pg` into `PrismaClient` — Prisma 7 requires a driver adapter. Read `DATABASE_URL` from `ConfigService`, not `process.env`.
- Register `PrismaModule` as `@Global()` in `shared/prisma/` so feature modules inject `PrismaService` without re-importing.
- On init, run `$queryRaw\`SELECT 1\`` as a connection smoke test while the schema has no models. That is the allowed raw-SQL exception until the first model exists.
- **NEVER** instantiate `PrismaClient` outside `PrismaService`.

## Schema Conventions

See `naming-conventions.md` for full rules:

- Tables: `snake_case`, **singular** — `user`, `order_item`.
- Columns: `camelCase` — `createdAt`, `userId`.
- Primary keys: `id`. Foreign keys: `{relatedTable}Id`.
- Map Prisma `@@map` and `@map` to match database naming when Prisma model names differ.
- **No entity files** — use Prisma-generated types in action services; expose API shapes via shared Zod schemas.
- Generate the client with `provider = "prisma-client"` and `moduleFormat = "cjs"`. Nest/webpack stays CommonJS. See `docs/adr/0001-prisma-client-commonjs.md`.

## Data Access Rules

- All Prisma calls live in **action services** — never in controllers or guards.
- Use `findUniqueOrThrow` / `findFirstOrThrow` and map to `NotFoundException` at the service boundary.
- Wrap multi-step writes in `prisma.$transaction()` when atomicity is required.
- Select only needed fields — avoid `findMany()` without `select` on large tables.
- Use `include` / `select` deliberately — avoid N+1 queries; prefer single queries with joins where appropriate.

## Migrations

- **ALWAYS** create migrations for schema changes — `nx run server:prisma-migrate`.
- **NEVER** edit production data via `prisma db push` without a migration strategy.
- **NEVER** commit an empty baseline migration. First migrate when the first model is added.
- Seed scripts live in `src/shared/prisma/seed.ts` — idempotent, safe to re-run in dev. Run with `nx run server:prisma-seed` (not on build). Prisma 7 does not seed automatically after migrate.

## CLI

- `prisma.config.ts` loads `apps/server/.env` via `dotenv`. Copy `.env.example` to `.env` and set the password. **NEVER** commit `.env`.
- Run Prisma through Nx so `cwd` is `apps/server`: `prisma-generate`, `prisma-migrate`, `prisma-seed`, `prisma-studio`.
- `build` and `test` `dependsOn` `prisma-generate`. Do **not** commit `generated/`.

## Rules

- **ALL** Prisma artifacts — `schema.prisma`, `migrations/`, `generated/` client output, and `seed.ts` — **MUST** live in `src/shared/prisma/`. The **ONLY** exception is `prisma.config.ts` at the application root. **NEVER** create a top-level `prisma/` directory.
- **NEVER** expose password hashes, tokens, or internal IDs unnecessarily in API responses.
- **NEVER** build raw SQL unless Prisma cannot express the query — document why if you do. The init `SELECT 1` smoke test is the current exception.
- **NEVER** duplicate types — infer from Prisma client types internally; validate API output with shared Zod schemas.
